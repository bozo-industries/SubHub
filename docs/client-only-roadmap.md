# Client-only roadmap

SubHub stays useful without an account, hosted service, or remote control plane. New ideas are ranked by how naturally they fit that boundary and by how much day-to-day value they add.

## Next

1. **Local tasks and rituals** — reusable routines, checklists, deadlines, proof notes, and streaks. This borrows the practical habit and reward loop seen in [Obedience](https://obedienceapp.com/habit-tracker) while keeping every task on the device.
2. **Local rewards and permissions** — a Dom-configured menu of earned permissions, treats, and cooldowns inspired by [Obedience Rewards](https://obedienceapp.com/rewards) and [UNION](https://www.union-relationship.app/ds-relationship-app). No remote approval is implied; the app records the local rule and result.
3. **Bounded rule deck** — opt-in random instructions drawn from packs with category, intensity, cooldown, quiet-hours, and hard daily caps. [Para2Go](https://mistressparadox.itch.io/para2go) demonstrates how a compact local instruction deck can create variety without a service.
4. **Check-ins and aftercare** — short mood, energy, consent-boundary, and aftercare prompts before and after service. [Kneel](https://getkneel.com/guide) and [UNION](https://www.union-relationship.app/ds-relationship-app) show the value of keeping structure and reflection beside the scene rather than treating them as separate tools.

## Later

- **Encrypted handoffs** — export a narrowly scoped, expiring bundle through QR, file share, or Android Nearby. A Dom can prepare rules on one device and a Sub can explicitly import them on another. There is no discovery directory, cloud relay, or silent remote mutation.
- **Local custody schedules** — time-bounded keyholding-style schedules and emergency release records informed by [ChastiSafe](https://chastisafe.net/index.html), implemented as ordinary local state rather than a hosted lock service.
- **Private scene journal** — encrypted local notes, milestones, and optional exports with no automatic upload.

## Product boundary

- Core features must remain fully functional offline.
- Peer exchange is explicit, encrypted, scoped, and initiated by both devices.
- Imported rules are previewed before acceptance and can never grant Android permissions.
- No internet-accessible phone server, background listener, account directory, or hidden remote command channel.
- Payment providers and GitHub release checks remain narrow external integrations, not SubHub infrastructure.

These references are inspiration for interaction patterns, not dependencies or endorsements.
